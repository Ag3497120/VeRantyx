# Shared GPU intermediate layer

VXRuntime will use one API-neutral GPU layer for its in-tree Direct3D 11, Direct3D 12 and Vulkan implementations. Each API remains a real front end with its own externally visible behavior. The shared layer is the internal boundary between those front ends and Metal.

```text
D3D11 (COM, implicit state, DXBC) ─┐
D3D12 (COM, explicit state, DXIL) ─┼─> common GPU IR ─> Metal backend
Vulkan (dispatch handles, SPIR-V) ─┘
```

## Responsibilities

| Layer | Owns |
|---|---|
| API front end | Windows ABI and object lifetime; API validation and capability reporting; API-specific resource states, descriptor rules, synchronization and presentation behavior |
| Common GPU IR | Device capabilities; resource and view descriptions; normalized descriptor layouts and bindings; pipeline descriptions; ordered render, compute, copy, clear, query and barrier operations; submission dependencies |
| Metal backend | Metal resource allocation and lifetime; pipeline creation/cache; command encoders and submission; Metal events, drawable acquisition and presentation |
| Shader front ends | DXBC, DXIL and SPIR-V decoding and validation, with stage and binding metadata |
| Shader backend | MSL generation from a shared typed shader representation when that representation covers the required semantics |

The common layer must preserve ordering and access information. D3D12 resource barriers and Vulkan image layouts/synchronization are interpreted by their front ends and lowered to explicit common resource accesses and dependencies. D3D11's implicit hazards and immediate-context ordering are tracked by its front end and expressed in that same form. A backend may optimize redundant transitions only after it has enough information to preserve the source API's observable behavior.

Descriptor sets, D3D12 root signatures/heaps and D3D11 register slots have different API rules. Their front ends validate those rules and lower the resulting bindings into a normalized layout; they do not expose D3D or Vulkan handles to the backend. A binding namespace preserves separate D3D12 SRV, UAV, CBV and sampler register files, while Vulkan uses namespace zero. Repeated register keys are retained only when their shader-stage visibility masks do not overlap. Vulkan's single binding per set/binding remains a single record with its declared stage mask. Capabilities are reported from the common backend's real support, with front ends translating those capabilities into each API's feature queries. Unsupported behavior must remain unsupported rather than being advertised optimistically.

Presentation follows the same boundary: DXGI and Vulkan WSI keep their surface and swap-chain contracts, while both use a common Metal drawable/present path where their lifetimes permit it.

The common stream includes repeated 1-, 2-, 4-, 8-, and 16-byte buffer patterns alongside buffer updates and copies. Vulkan checks `vkCmdFillBuffer` usage, four-byte alignment and range rules in its front end, then records a 32-bit fill. D3D11 typed, raw and structured buffer UAV clears retain their own format, stride and element-range rules, then record the corresponding common pattern fill. D3D12 raw-buffer clears, typed `R`, `RG` and `RGBA` 8-, 16- and 32-bit integer buffer clears, and packed `R10G10B10A2_UINT` buffer clears also preserve their descriptor ranges and record common pattern fills; other typed formats and texture views keep the D3D12-specific clear path. Metal stages a bounded repeated pattern and encodes ordered blit copies; narrow subranges that Metal cannot copy with its alignment rules use a synchronous shared-memory write in the reusable submission backend.

Color and depth/stencil clears now use common commands. The stream retains the selected texture and snapshots signed, half-open pixel rectangles; an empty list means the whole selected attachment. The reusable `gpu_ir_metal` submission backend executes full clears as render-pass load actions and rectangular clears with scissored raster work. D3D12 preserves its RTV/DSV and resource-state validation in the front end, then uses the same Metal clear encoders inside command-list replay. Vulkan `vkCmdClearColorImage` records full clears through this shared path for its currently supported linear 2D transfer images; depth/stencil clears, image views, render passes and graphics remain future Vulkan work.

## Migration stages

1. Define API-neutral resource, view, format, descriptor-layout, pipeline and command records. Keep API handles and validation in their existing front ends. Implemented slices are reference-counted buffer/texture resources, reference-counted typed/structured/raw buffer views with range and access validation, immutable descriptor and push-constant layouts, retained sparse descriptor-state snapshots with primary and optional auxiliary resource accesses and ordered bind commands, retained graphics/compute pipeline records, direct and indirect compute dispatch including fixed-stride ranges with optional count buffers, indexed/non-indexed draw recording, whole-resource stage/access annotations on draw and dispatch commands, ordered buffer/full-resource/texture-region copies, multisample resolves, attachment clears and resource barriers.
2. Lower the remaining D3D12 command-list operations and submission to the common records, then move their execution behind the Metal backend. Ordinary compute dispatches and draw calls now use common pipeline/operation records; D3D12 resource, descriptor, root-argument, attachment and queue validation remains in `d3d12.m`.
3. Move the remaining D3D11 resource and descriptor binding references onto the same resource and command interfaces. Keep its immediate-context semantics, render-pass decisions and cross-process IOSurface behavior in the D3D11/DXGI front ends.
4. Expand the Vulkan front end, which now has dispatchable/non-dispatchable handles, basic feature queries, storage-buffer descriptor sets, buffer synchronization, compute dispatch, `vkCmdClearColorImage`, and a linear 2D transfer-image slice with buffer/image and image/image blits. Add optimal images, image views/descriptors, graphics, broader synchronization and WSI.
5. Keep the existing DXBC→MSL and DXIL→MSL paths while the API IR stabilizes. The owned typed shader IR, first SPIR-V lowering slice, narrow compute MSL emitter, and initial DXIL-to-common-IR adapter now exist. D3D12 direct compute dispatches use a common-IR MSL pipeline when both DXIL lowering and Metal pipeline creation support the shader; unsupported shaders and indirect dispatch retain the direct DXIL-to-MSL path. Expand the shared shader subset and DXIL adapter operation by operation, then add a DXBC adapter and Vulkan API integration without bypassing front-end validation.

This stages shader unification separately from API command/resource unification. D3D11 `CopyResource` and `CopySubresourceRegion` buffer/texture copies now lower through the common records, alongside D3D12 copies, resolves and barriers. D3D11's ordinary immediate-context draw and compute dispatch calls now execute through common GPU IR commands; the front end still owns its bound state, geometry-shader and stream-output paths, and descriptor binding. D3D12 compute and graphics PSO creation now creates retained common pipeline records. Ordinary D3D12 `Dispatch`, `DrawInstanced` and `DrawIndexedInstanced` calls execute through common operations. `ExecuteIndirect` signature decoding and argument-driven D3D12 state changes remain in its front end; fixed-signature `DISPATCH` and draw operations use common indirect operations, including retained optional count buffers, while expanded fallback draw/dispatch commands use transient common operations. The typed `R32_SINT`, `R32_UINT` and `R32_FLOAT` buffer compute subsets lower through common DXIL shader IR and common MSL on D3D12 direct dispatch. Runtime GPU tests cover each format, including `FirstElement`, `GetDimensions`, signed and floating arithmetic, and readback. The descriptor table is snapshotted from the current root binding and encoded into dense Metal buffer slots. Other supported-by-direct-translation shaders keep the direct DXIL MSL pipeline when common lowering or compilation does not support them, and indirect dispatch still uses that direct pipeline. The Vulkan compute front end creates immutable descriptor snapshots and records descriptor-state binds with dispatch commands. During D3D11 draws and dispatches, reflected CBV/SRV/UAV/sampler bindings are resolved into temporary common descriptor snapshots for resource-access annotation. Buffer SRV/UAV entries also carry typed, structured or raw element ranges when the view and resource metadata identify them; MSL argument encoding still uses D3D11 state. During D3D12 replay, finite reflected root-table/root-descriptor bindings and static/table samplers are resolved into a temporary common descriptor snapshot for resource-access annotation; hidden UAV counters are carried as auxiliary buffer accesses. The common DXIL path binds the subset it supports from that snapshot; remaining MSL argument encoding and direct `ResourceDescriptorHeap` indexing use D3D12-specific state. The remaining migration must preserve each front end's own validation and ordering rules.

Draw and compute commands can retain conservative whole-resource access annotations with shader stage and access masks, and the common layer validates the resource kind and pipeline-stage compatibility. D3D12 replay resolves reflected root descriptors and descriptor tables against the currently bound command-list state, then annotates shader resources, vertex/index buffers and render attachments. Direct `ResourceDescriptorHeap` indexing conservatively checks and annotates live entries whose SRV, UAV or CBV class is used by the shader; this may include entries the dynamic index does not select. The Metal D3D12 callbacks pass those annotations to `useResource` with the corresponding read/write usage and render stage. D3D11 ordinary draws and compute dispatches resolve DXBC resource masks and bound CBV/SRV/UAV/sampler values into a temporary common descriptor snapshot, then derive accesses for bound shader resources, vertex/index buffers and attachments and pass them through common commands to Metal `useResource`. Its geometry-shader and stream-output paths still use API-specific command execution. The existing all-resource residency fallback remains in place, and resource annotations do not yet drive barrier elimination or hazard inference.

## Current implementation boundary

The D3D11 translator in `dxbc.c` emits MSL directly. The D3D12 reader in `dxil.c` and translator in `dxil_msl.c` are also in-tree and emit MSL without LLVM. The common GPU IR in `gpu_ir.h`/`gpu_ir.c` handles retained buffer and texture references; typed, structured and raw buffer-view ranges and lifetime; immutable descriptor layouts keyed by set, namespace and binding with descriptor kinds, array counts, stage visibility and access masks; optional auxiliary buffer accesses attached to descriptor snapshots; push-constant ranges; retained graphics/compute pipeline records, direct and indirect compute-dispatch commands including fixed-stride ranges with optional retained count buffers and offsets, direct indexed/non-indexed draw commands, and fixed-stride indirect draw commands with optional retained count buffers and offsets; D3D11 full-resource and buffer/texture-region copies; D3D12 buffer/full-resource/texture-region copies; multisample resolves with explicit source/destination rectangles; ordered transition/UAV/aliasing/global barriers; and scoped memory, buffer and image dependencies. D3D12 typed buffer SRV/UAV descriptors now create Metal texture-buffer views through the common view object. The view's normalized base range and element count feed descriptor construction, and DXIL MSL applies `FirstElement` and `NumElements` to typed loads, stores and `GetDimensions`. Raw and structured buffers remain byte-addressed. The layout validator permits repeated binding keys only when their stage masks are disjoint, descriptor/access compatibility, shader-stage masks, push-constant alignment and stage-overlap rules. D3D12 root-signature creation now builds a normalized layout record for descriptor tables, root descriptors and static samplers. The front end still keeps its native root-signature records for descriptor-table offsets, root-constant registers and command-list binding; root constants are not misrepresented as Vulkan-style byte ranges. `spirv_ir.c` maps SPIR-V descriptor declarations and supported push-constant blocks into common layouts for a selected entry point. The Vulkan compute front end uses those common records for storage-buffer descriptor sets and dispatch. During D3D12 replay, reflected root tables/root descriptors and static/table samplers are captured in temporary common descriptor-state snapshots used to derive common resource-access annotations, while the actual D3D12 root argument encoding remains in the API front end. D3D11 descriptor binding remains API-specific. Texture metadata carries block dimensions and bytes per block, so the common copy validator handles BC block alignment and the Metal backend uploads and reads back BC data with block-row pitches. D3D12 validates resolve format families, dimensions, sample counts and subresources, and validates barrier kinds, flags, state masks, resource flags, resolve sample counts and subresource bounds before recording. Its front end carries each resource's creation state and sparse per-subresource overrides, checks transition before-states and split-barrier pairing in serialized queue submission order, validates copy and resolve states, and requires ExecuteIndirect argument/count buffers to be readable in `INDIRECT_ARGUMENT`. COMMON-state use follows the D3D12 promotion table for buffers and eligible textures; promoted read states can merge, and eligible resources decay at the end of an `ExecuteCommandLists` call, never between lists in that call. UPLOAD and READBACK buffers retain their creation, access and barrier restrictions while following buffer decay at submission boundaries. Command operations are checked against Direct, Compute, Copy, and command-list capabilities. Direct lists snapshot a restricted graphics bundle subset at ExecuteBundle recording time; bundle draws inherit target/root state, and PSO, topology, root bindings and IA bindings changed by the bundle flow back to the parent. Descriptor heaps set by a bundle must match the parent heaps, and bundles cannot be submitted directly. The supported ExecuteIndirect bundle form is one Draw or DrawIndexed operation with no count buffer or root/IA updates. It also maps RTV/DSV descriptors back to their resource and view subresource, checks clear and draw attachment states (including read-only depth/stencil flags), checks bound vertex/index buffer states, and validates reflected finite CBV/SRV/UAV descriptor bindings at draw/dispatch against their required D3D12 states. Root-signature parsing rejects unknown root flags and invalid v1.1 descriptor-range/root-descriptor volatility flag combinations; SM 6.6 direct heap use requires the matching root-signature opt-in at PSO creation, and submission requires the corresponding shader-visible heap of the correct heap type to be bound. Submission checks every live descriptor in each direct resource-heap class used by DXIL against the required D3D12 state; access annotations carry matching CBV/SRV/UAV access masks. This conservative check can include entries a dynamic index never selects. A per-list update is transactional so a rejected list cannot partially advance tracked states. GPU-only root/IA-updating ExecuteIndirect inputs are per-record validated during preflight when the current list has no preceding GPU work; GPU-produced records later in that same list are staged after the producer prefix and passed through whole-list per-record state validation before expansion, with invalid records skipped; cross-queue ownership/fence semantics, other queue-type restrictions, partial D24S8/D32S8 and stencil-plane/decompress resolves, and Vulkan synchronization remain unvalidated. Metal resolves supported full color average subresources with a render-pass resolve; partial color average resolves use a cached Metal shader that averages all samples over the selected source rectangle and writes only the destination rectangle for normalized and floating-point formats. Color MIN/MAX resolves use typed Metal fragment pipelines for the supported normalized/floating-point and integer format set, including full subresources and partial rectangles; a varying-sample RGBA8 array test checks reduction results and preserves pixels outside the destination region; an RGBA8_UINT test compiles and executes the typed integer pipeline for partial MIN/MAX and full MAX. Metal replay closes active encoders at barriers so Metal's tracked-resource hazard handling orders those encoders. Texture copies with formats that do not map to a Metal texture still use the existing D3D12 replay path or remain unsupported by the backend. D3D11 resource views and descriptor binding; Vulkan objects and WSI; full common descriptor-state command binding for D3D11/D3D12/Vulkan; GPU-side ExecuteIndirect lowering for signatures that change root or IA state; and several D3D12 indirect state-validation cases remain unfinished. D3D11 geometry-shader and stream-output submission still uses API-specific lowering. D3D11 typed UAV atomic operations, device-specific texture-buffer format support reporting, and D3D12 UAV view-dimension fields beyond the implemented 3D W-slice range remain incomplete. D3D12 structured-buffer UAV counters now lower through DXIL BufferUpdateCounter and are represented as auxiliary GPU IR buffer accesses. The graphics path links Apple's Metal framework; it does not use D3DMetal or Game Porting Toolkit.

`spirv_ir.c` maps SPIR-V descriptor declarations and supported push-constant blocks into common layouts for the selected entry point. Push-constant extents use explicit member offsets, fixed array strides, matrix strides/major order, and scalar/vector/nested-struct sizes; runtime/specialization arrays and unsupported types are rejected. The Vulkan frontend validates the supported storage-buffer set-layout subset and range/alignment; entry-point reflection remains module-conservative.

The SPIR-V compute adapter also lowers 32-bit float scalar and 2–4 lane vector `GLSL.std.450` operations `FAbs`, `Floor`, `Ceil`, `Trunc`, `Fract`, `Round`, `RoundEven`, `Sqrt`, `InverseSqrt`, `Sin`, `Cos`, `Tan`, `Asin`, `Acos`, `Atan`, `Sinh`, `Cosh`, `Tanh`, `Asinh`, `Acosh`, `Atanh`, `Exp`, `Log`, `Exp2`, `Log2`, `Pow`, `FMin`, `FMax`, `FClamp`, and `Fma` into common arithmetic operations. The MSL emitter maps them to Metal math functions. Other extended-instruction sets and operation numbers are rejected explicitly; this slice does not advertise broad extended-instruction support.

`CopyTextureRegion` keeps D3D12 subresource and placed-footprint interpretation in `d3d12.m`, then records normalized source/destination locations and extent in the shared stream. The common layer checks mip/slice bounds, texture extents, buffer footprint dimensions, row/image pitches, and backing buffer ranges. The D3D12 front end checks the selected subresources are in COPY_SOURCE/COPY_DEST before submission, and the Metal callback performs the blit in command-list order. `ResolveSubresource` validates compatible D3D12 format families and source/destination state, then records an average resolve; Metal uses a color render-pass store action or the D16/D32 depth-average shader path. `ID3D12GraphicsCommandList1::ResolveSubresourceRegion` records its source rectangle, destination offset, extent and mode in common GPU IR. Full-subresource color average resolves use Metal's render-pass resolve; color average partial rectangles and destination offsets use a cached fragment pipeline for supported normalized and floating-point formats, with a GPU test confirming pixels outside the destination rectangle are preserved. Full-subresource depth MIN/MAX resolves use Metal’s depth attachment filter, while D16/D32 depth AVERAGE uses a custom fragment pipeline, on Apple GPU family 3 or later. Partial D16/D32 AVERAGE/MIN/MAX resolves use a scissored depth-writing fragment pipeline with load/store semantics, preserving pixels outside the destination rectangle; the tested array path selects source and destination slices. Partial D24S8/D32S8, depth average outside D16/D32, stencil-plane and decompress resolves remain unsupported and are rejected during recording. `ResourceBarrier` translates D3D12 state masks into common access masks and records each array entry in order; the D3D12 front end separately matches before/after states per subresource, including paired split transitions, when serialized submissions reach the queue. Invalid lists are rejected before any state changes are committed. Metal uses encoder boundaries and tracked-resource hazard handling for backend ordering. D3D12 commands without a supported common resource representation retain the earlier replay route.

The common barrier record now has separate 64-bit synchronization-stage scopes and access scopes, dependency flags, concrete buffer ranges, image aspect/mip/layer ranges, normalized old/new image layouts, and queue-family indices. Its memory, buffer, and image dependency forms preserve those fields through the backend callback and validate resource kind and range bounds. API front ends still own the source API's validation and mapping; the Vulkan frontend lowers supported memory, buffer and single-color-subresource image barriers, and rejects unsupported ownership transfers and stage/access flags. The Metal backend orders image transfer work at encoder boundaries and uses texture/buffer memory barriers inside compute encoders. The common scope names are independent of Vulkan numeric bit values, so a Vulkan frontend must translate explicitly and reject flags it cannot represent.

D3D11 `ClearUnorderedAccessViewUint` handles raw and structured buffer views with the API's `Values[0]` dword pattern, and typed buffer views with per-channel low-bit patterns for supported 8-, 16-, and 32-bit formats. The front end converts `FirstElement` and `NumElements` using the view's element size or structured stride, then records a common GPU IR pattern fill. Tests read back structured, R16_UINT and RGBA8_UINT ranges, including untouched prefixes and suffixes.


`gpu_ir_metal.m` provides a reusable Metal device/queue, shared buffer resources, buffer-backed linear textures, common-IR compute pipeline compilation, descriptor-state binding, buffer/texture copies, record-time buffer updates, direct and indirect compute dispatch, and buffer/image-scoped barriers. Its stream submission is synchronous. Descriptor binding supports finite compute-visible storage-buffer bindings and fixed-size arrays in namespace zero, plus D3D12 read-only/storage resources in namespaces zero and one, with dense Metal slot assignment. The Vulkan frontend supports single-mip, single-layer RGBA8 transfer images, storage-image reads/writes, and sampled-image Lod-0 texel fetch. Runtime-sized or dynamically indexed descriptor arrays, graphics, filtered sampling, other descriptor kinds, and asynchronous queue behavior remain unconnected. Both the SPIR-V integration test and Vulkan compute frontend build descriptor snapshots and submit bind/dispatch streams through this backend.

The D3D12 front end now lowers `ClearRenderTargetView` and `ClearDepthStencilView` into the common color and depth/stencil clear records. Those records own their rectangle snapshots and retain the selected Metal texture view; the common Metal backend handles full-view load-action clears and partial rectangle raster clears. Its queue-side state checks still run against the original API resource and subresource. Vulkan `vkCmdClearColorImage` also lowers its supported full-image clear into the common record after checking transfer-destination usage, the passed layout, color aspect and the single mip/layer supported by the current image implementation. Vulkan queue-submit preflight now checks image-layout transitions and uses in submit order, applying transitions transactionally and honoring `UNDEFINED` as a content discard. Depth/stencil clears and per-subresource state beyond the current single-mip/single-layer images remain unfinished.

## DXIL shader verification

`tests/shaders12/samplegrad_ps.hlsl` covers `SampleGrad` for 1D and 1D-array, 2D and 2D-array, 3D, cube and cube-array textures. The translator uses the active gradient components for each texture dimension and omits the array layer from the gradient, then Metal compiles the generated MSL as part of `dxil2msl`. It also covers the optional minimum-LOD clamp. Metal 1D texture sampling has no explicit LOD option, so the 1D cases use Metal's implicit sampling gradients; explicit 1D gradients and their clamp cannot be preserved on this backend.

The DXIL-to-common-IR adapter lowers compute-stage `dx.op.barrier` (opcode 80) modes into common control-barrier and memory-barrier operations. DXIL `extractelement`/`insertelement` and SPIR-V `OpVectorExtractDynamic`/`OpVectorInsertDynamic` lower to typed Metal vector indexing for 32-bit integer indices; static DXIL `extractvalue`/`insertvalue` and SPIR-V `OpCompositeExtract`/`OpCompositeInsert` support one vector-lane index. Insertions copy the source vector before replacing the selected lane. Dynamic extraction and insertion keep the source-language out-of-range behavior (undefined or poison); the emitter does not clamp indices. It also lowers typed `R32_SINT`, `R32_UINT` and `R32_FLOAT` buffer SRV/UAV `BufferLoad`, `BufferStore`, and field-zero `GetDimensions`, including statically indexed single-descriptor `CreateHandle`. Float loads and stores use 32-bit bitcasts around the common byte-addressed `uint` buffer access, preserving the element bits while leaving range checks in bytes. Signed and unsigned integer views share the byte-addressed `uint` storage representation; DXIL's signed division, remainder, arithmetic right shift, comparisons, and scalar/vector `fptosi` and `sitofp` retain the operation's signed semantics in common IR, and MSL reinterprets 32-bit integers with `as_type` where needed. Scalar numeric `null` constants lower to zero, including zero indices emitted by DXC. LLVM fast-math instruction flags are retained as a common shader hint; the MSL backend emits the regular arithmetic expression. The adapter checks resource metadata, handle class, formats, offsets, masks and aggregate fields; unsupported buffer shapes, descriptor indexing, and operations still return `GPU_IR_UNSUPPORTED`. SRVs are represented as read-only resources and emit `device const uint*`; UAVs emit writable pointers. The common MSL path maps D3D12 SRV/UAV namespaces through the root-signature layout, snapshots the currently bound descriptor table, and executes direct compute dispatches on the same Metal device as the D3D12 backend. The ordinary `typed_buffer_cs.dxil` D3D12 runtime test covers nonzero `FirstElement`, `NumElements`, `GetDimensions`, dispatch and readback for `R32_UINT`. `typed_sint_buffer_cs.dxil`, compiled from `Buffer<int>` by the in-tree DXC runner, executes a negative `-40 / 2` through common DXIL IR and MSL with `R32_SINT` SRV/UAV views; readback verifies `-20`. Its adapter test confirms the signed divide flag and compiles the generated MSL. `signed_conversion_cs.dxil` runs through the common-IR D3D12 path: `-8` is converted with `sitofp`, multiplied and offset, then converted with `fptosi`; readback verifies the float bits `0xc1000000` and integer bits `0xfffffff5`. `typed_float_buffer_cs.dxil` exercises real `R32_FLOAT` SRV/UAV loads and stores, `FirstElement`, `GetDimensions`, unsigned-to-float conversion, arithmetic, common MSL compilation, D3D12 dispatch and readback (`3.5` produces `5.75`). Indirect dispatch and shaders outside the common subset continue through direct DXIL-to-MSL.

The DXIL common-IR adapter also lowers scalar 32-bit `Bfrev`, `Countbits`, `FirstbitLo`, `FirstbitHi`, `FirstbitSHi`, `Ibfe`, `Ubfe`, and `Bfi` intrinsics (opcodes 30–34 and 51–53). It reorders DXIL's width/offset-first arguments into the common bit-field operation order, preserves signed extraction for `Ibfe`, and masks width and offset to their low five bits as required by DXIL. `dxil_bit_intrinsics.metal` is generated from a synthetic DXIL function with the same declaration and call signatures, checks all eight normalized IR operations and operand order, and is compiled by the Metal compiler during `make check`. The DXIL adapter currently rejects vector and non-32-bit overloads. The common MSL bit-scan lowering also handles SPIR-V `GLSL.std.450` `FindILsb`, `FindSMsb`, and `FindUMsb` for 32-bit scalar and 2–4 component vector values, including the all-bits-set result for zero (and for signed MSB inputs 0 and -1). It converts `clz` to a bit index with `31 - clz`; a Metal runtime shader test checks ordinary and edge-case values. See Microsoft's [DXIL operation specification](https://github.com/microsoft/DirectXShaderCompiler/blob/main/docs/DXIL.rst#operations-via-external-functions) and Khronos's [GLSL extended-instruction specification](https://registry.khronos.org/SPIR-V/specs/unified1/GLSL.std.450.html).

The DXIL adapter also normalizes `dx.op.unary` opcodes 6–29 into common IR: absolute value, saturate, scalar `isnan`/`isinf`/`isfinite`/`isnormal`, trigonometric and hyperbolic functions, base-2 exponential/logarithm, square root/reciprocal square root, fractional part, and the four rounding modes. This slice accepts 32-bit float scalars and 2–4 lane vectors for arithmetic, and scalar float inputs with scalar boolean results for classification. `Round_ne` maps to ties-to-even (`rint` in MSL), while `Round_ni`, `Round_pi`, and `Round_z` map to floor, ceil, and truncation. A synthetic DXIL fixture checks every opcode's common operation and generated MSL; `make check` compiles that MSL. Other overloads and unlisted DXIL operations remain on the direct translator or return unsupported. The mapping follows Microsoft's [DXIL operation specification](https://github.com/microsoft/DirectXShaderCompiler/blob/main/docs/DXIL.rst#operations-via-external-functions).
